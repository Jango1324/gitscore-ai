# GitScore Evaluation Corpus (Milestone 8C)

Evaluation-only artifacts measuring the real GitScore pipeline against
hand-authored gold expectations. **Not production code** — nothing
under `src/gitscore/` depends on anything in this directory, and
nothing here changes product behavior. See
`docs/evaluation/MILESTONE_8C_EVALUATION.md` for the full findings
report.

**Corpus version:** `8c:v1`.

## Layout

```
evaluation/
  jobs/                   15 synthetic, hand-authored job descriptions
  gold/
    jobs/                 evaluator-authored expected requirements per job
    candidates/           evaluator-authored expected evidence/ranking per candidate
    matrix.json           the candidate x job evaluation matrix (strategic pairs)
  fixtures/
    candidates/           offline snapshots of 4 real GitHub accounts (collected once each)
  reports/                generated by scripts/evaluate_*.py (JSON + Markdown)
```

## Running the harness

All three scripts are offline (they read only `evaluation/fixtures/`,
never GitHub) and deterministic:

```bash
python scripts/evaluate_job_parser.py     # Layer A: job-description parser
python scripts/evaluate_evidence.py       # Layer B: candidate evidence + repository ranking
python scripts/evaluate_end_to_end.py     # Layers C/D: matcher + assessment, candidate x job matrix
```

Each writes `evaluation/reports/<name>_report.{json,md}`. Exit code 0
means the harness ran successfully — it says nothing about how many
evaluation findings were reported; those are measurements, not test
assertions. A non-zero exit means a corpus/fixture file was missing or
malformed.

## Corpus provenance

- **Jobs** (`jobs/*.json`): synthetic postings authored specifically for
  this evaluation (see each file's `source_note`) — never copied or
  paraphrased from a real company's listing.
- **Gold** (`gold/jobs/*.json`, `gold/candidates/*.json`): written
  independently by reading the job text / the candidate's raw repository
  list, never by running the parser/extractor first and copying its
  output.
- **Candidate fixtures** (`fixtures/candidates/*.json`): one real,
  public GitHub account snapshot per file, collected ONCE via an ad hoc
  (non-deliverable) script that mirrors exactly what
  `gitscore.pipeline.evidence.extract_candidate_evidence()` fetches.
  Each fixture records `collected_at`, `repository_ranking_version`,
  `evidence_schema_version`, and `api_request_count` for reproducibility
  context — GitHub repositories change over time, so re-collecting will
  not reproduce byte-identical results indefinitely.

## Updating the corpus

Bump `EVALUATION_CORPUS_VERSION` in `scripts/evaluation_lib/taxonomy.py`
(and in every job/gold/fixture file's own `corpus_version` field)
whenever a job, gold annotation, or candidate fixture changes in a way
that could change evaluation results — this versions the *benchmark
data*, never GitScore's own analytical semantics
(`JOB_REQUIREMENT_SCHEMA_VERSION`, `MATCHER_VERSION`, etc., which this
milestone does not touch).
